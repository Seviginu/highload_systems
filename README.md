# Task tracker — лабораторные работы по JVM

Java 21, Maven, Spring Boot. После ЛР2 проект состоит из `user-service` (WebFlux/R2DBC), `tracker-service` (WebFlux/JPA), Gateway, Eureka и Config Server. PostgreSQL и Redis запускаются через Docker Compose.

## Пароли и bootstrap

В `POST /api/v1/users` добавлено обязательное поле `password`: минимум 8 символов, максимум 72 байта UTF-8. В БД сохраняется BCrypt-хэш с индивидуальной солью. Ответы пользователя и внутреннего API не содержат пароль или хэш. Обычное обновление пользователя пароль не меняет.

Миграция сохраняет существующих пользователей и их ID; у старых записей `password_hash` остается NULL. Пока супервайзер не назначит им пароль, вход для них закрыт.

Для создания первого супервайзера скопировать `.env.example` в `.env` и задать:

```dotenv
BOOTSTRAP_ADMIN_ENABLED=true
BOOTSTRAP_ADMIN_NAME=Supervisor
BOOTSTRAP_ADMIN_EMAIL=supervisor@example.com
BOOTSTRAP_ADMIN_PASSWORD=<ваш пароль>
```

`ADMIN` — супервайзер из задания. Bootstrap включается явно и создает его только при отсутствии активного ADMIN с заданным хэшем пароля. Если указанный email занят любой существующей записью, создание завершится ошибкой: bootstrap не повышает ее роль и не сбрасывает пароль. При повторном запуске с существующим ADMIN с паролем ничего не меняется, даже если изменить bootstrap-параметры. После первичной настройки bootstrap можно отключить.

Запуск:

```bash
./scripts/docker-up.sh
```

Скрипт создает локальную RSA-пару в `.local/jwt`, сохраняя существующий приватный ключ. Приватный ключ монтируется только в user-service, публичный — также в Gateway и tracker-service. Параметры issuer, audience и TTL задаются окружением. Каталог `.local` исключен из git и Docker build context.

Скрипт использует `GATEWAY_PORT=58081` по умолчанию: общий Swagger — `http://localhost:58081/swagger-ui/index.html`. Он ожидает healthy-состояние сервисов и доступность обеих OpenAPI-схем через Gateway; таймаут задается `STARTUP_TIMEOUT_SECONDS` (по умолчанию 180 секунд). При запуске непосредственно через `docker compose up --build -d` без переопределений используется порт 8081; перед первым запуском выполнить `bash scripts/generate-jwt-keys.sh`.

## Вход и доступ

1. Выполнить `POST /api/v1/auth/login` с email и паролем супервайзера. Получить `accessToken`, `tokenType=Bearer` и `expiresIn` в секундах.
2. Передавать токен в `Authorization: Bearer <accessToken>`. В Swagger нажать Authorize и вставить JWT без префикса Bearer. Общий Swagger содержит документацию обоих сервисов.
3. `GET /api/v1/auth/me` возвращает актуальный профиль текущего пользователя.
4. Только ADMIN может создавать, читать, изменять и удалять пользователей и назначать роли. Для назначения или изменения пароля существующего пользователя использовать `PUT /api/v1/users/{id}/password` с телом `{"password":"новый пароль"}`; успешный ответ — 204.

JWT подписывается RS256, содержит ID пользователя в `sub`, роль, issuer, audience и срок действия. Gateway и оба бизнес-сервиса независимо проверяют подпись и claims. Отсутствующий или невалидный JWT дает 401, недостаток прав — 403; ошибки возвращаются в формате `ApiError`. Сессии, form login и HTTP Basic не используются.

Внутренний `/internal/users/resolve` требует JWT и не маршрутизируется Gateway. Feign получает исходный токен явным параметром через worker-вызов; 401/403 downstream не считаются сбоями доступности для Circuit Breaker.

По умолчанию JWT живет 15 минут. После смены роли, пароля или удаления пользователя ранее выданный JWT действует до истечения TTL; новый вход проверяет актуальную БД, а `/auth/me` отклоняет удаленного пользователя. Refresh tokens и немедленный отзыв не реализованы.

## Права на проекты и задачи

| Операция | ADMIN | TEAM_LEAD | DEVELOPER |
|---|---|---|---|
| Чтение проектов, задач, меток и участников | Да | Да | Да |
| Создание проекта | С выбранным тимлидом | Только с собственным `teamLeadId` | Нет |
| Изменение/удаление проекта и управление участниками | Любой проект | Проект с активным членством | Нет |
| Создание, полное изменение, удаление задачи | Любой проект | Проект с активным членством | Нет |
| Перенос задачи | Да | Активное членство в обоих проектах | Нет |
| Изменение статуса задачи | Да | Проект с активным членством | Назначенная задача и активное членство |
| Создание/изменение/удаление глобальных меток | Да | Нет | Нет |

`POST /api/v1/tasks` определяет автора по `sub` JWT. Поля `authorId` во входных DTO создания и обновления больше нет; автор в ответах сохраняется, при обычном обновлении он неизменяем. Назначаемый исполнитель должен быть активным участником проекта, в том числе при создании и обычном обновлении задачи.

Для изменения статуса использовать `PATCH /api/v1/tasks/{id}/status`:

```json
{"status":"IN_PROGRESS","version":0}
```

`version` брать из последнего ответа задачи. Устаревшая версия дает 409. Проверки прав используют актуальную запись БД; прогретый кэш не позволяет обойти запрет. После успешного PATCH кэш обновляется, при 403/409 запись и кэш не меняются.

Текущий пользователь извлекается из проверенного Reactor Security Context до перехода на `tracker-blocking`, затем явно передается в синхронный сервис и Feign. Чтение трекера открыто всем аутентифицированным ролям; фильтрация видимости по проектам не предусмотрена.

`security-common` — общая библиотека проверки JWT и формирования ошибок. Тестовая RSA-пара находится только в test resources этой библиотеки и не используется конфигурацией приложения или исполняемыми JAR.

Проверка на JDK 21 с доступным Docker:

```bash
mvn clean verify
```

Интеграционные тесты используют отдельные PostgreSQL/Redis Testcontainers. Рабочие Compose volumes для тестов не требуются.
